# 백엔드 학습 로드맵 — 광고심의 워크스루

> 목적: 작성된 코드의 **모든 "왜?"에 스스로 답할 수 있는 상태**가 되기.
> 어디서든(폰·집·회사) 이 문서와 카드로 이어서 학습한다.

## 학습 방법 — 이해의 4층

| 층 | 질문 | 도구 |
|---|---|---|
| 1. 계약 | 뭘 하는 코드인가 | 테스트 `@DisplayName` 목록 |
| 2. 구현 | 어떻게 하는가 | diff 리딩 + 문법 노트 |
| 3. 결정 | **왜 이 방식인가** | 결정 카드 (`cards/`) ← 동료 질문의 대부분 |
| 4. 체화 | 진짜 이해했는가 | 역설명 + 깨보기 실습 (`qa-bank.md`) |

**사이클** (새 기능마다):

```
① 계약 먼저 — 코드 없이 테스트 이름 목록 제시
② 내가 승인 — "이 동작이 맞다"
③ 구현 + 결정 카드 동시 작성
④ 워크스루 — diff + 문법 노트 + 결정 카드
⑤ 역설명 — 내가 AI에게 설명하고 검증받기
⑥ 커밋 — 내가 직접
```

**깊이 예산**: 결정(3층)은 전부 깊게 / 로직은 테스트로 계약만 / 보일러플레이트는 훑기.

## 진행 현황

| # | 덩어리 | 내용 | 상태 |
|---|---|---|---|
| ① | 목록 조회 | 느슨한 참조 조인 + 이름검색 + 하위조직 확장 | ✅ 워크스루 완료 → [카드](cards/01-list-query.md) |
| ② | 자동발번 | 번호 채번 + 유니크 충돌 재시도, **왜 @Transactional을 뺐나** | ⏳ 다음 차례 |
| ③ | 승인일 자동 | 상태 전환 감지, 클라이언트 값 무시 | 대기 |
| ④ | 의견 | 목록 조회 + body 단순화 + 작성자 403 | 대기 |
| ⑤ | 엑셀 | POI 생성 | 대기 |
| ⑥ | 예외 핸들러 | catch-all 이 상태코드를 삼키는 문제 | 대기 |
| ⑦ | 프론트 반영 | 조인 표시·검색칸·의견 서버 조회 + C그룹(삭제순서·와일드카드·가짜팝업 제거·alert큐·타입좁힘) | ✅ 구현 완료, 워크스루 대기 |
| ⑧ | 테스트 코드 | 단위 테스트 리딩 — BE 29개 + FE 8개, 전부 green | 준비됨 — 테스트 이름이 곧 의도 명세 |

워크스루가 끝난 덩어리만 커밋 대상이 된다 — 커밋 이력 = 내가 이해하고 승인한 단위.

## 장소별 역할

- **회사 책상 (Claude Code)**: 코드 작업, 워크스루, 테스트 실행
- **이동 중/집 (OpenClaw·폰)**: 결정 카드 복습, `qa-bank.md`로 역설명 연습
- **폐쇄망 전환 후**: 이 저장소의 카드 + 회사 저장소의 테스트·주석만으로 자립

## 보안 규칙 (이 저장소는 개인 저장소)

- 회사 코드 **원문 금지** — 일반화한 패턴 스니펫만
- 호스트명·계정·비밀번호·내부 URL 금지
- 커밋 메시지에도 민감정보 금지
